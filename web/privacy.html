Common Ground

Privacy notice

How this app handles what you enter, and what its hosting and taste-data providers receive.

This notice explains what Common Ground does with the information you enter. It is current as of 30 October 2026.

What you enter

The night planner asks for a city, an optional night date, 2 to 6 friend names, and 1 to 4 favourites for each friend. The single-pick flow asks for a category, a city when you pick a restaurant, 2 to 8 names, and 2 to 5 favourites for each person. Favourites are free text, such as music artists, films, TV shows or books.

The app does not ask for an account, login, payment, booking, email address, phone number, postal address, government ID or other sensitive personal data. Do not enter sensitive information about yourself or anyone else.

What the app sends, and to whom

When you submit the form, your browser sends the entered values as JSON to the app's Cloudflare Worker at /api/night or /api/pick. Member names, favourites, city and the optional date reach that Worker.

In live mode the Worker uses Qloo to turn favourites into recommendations:

  • Each favourite is sent to Qloo's search endpoint as the text you typed. The app does not anonymize that text before sending it.
  • Matched entity IDs are sent to Qloo's Insights endpoint, together with the city for restaurant or other place picks and for every night stop. If you chose a date, the derived weekday is sent as Qloo's opening-day filter for those place calls.
  • Candidate entity IDs are sent when Qloo scores a shared pool of candidates.

The Qloo request parameters in the source do not include member names as a separate field. If you type a person's name into a favourite field, it is treated as a favourite and sent as text. The Worker keeps names for matching results back to the right friend and for showing the result in your browser. Qloo returns entity details and affinity scores to the Worker, and the Worker returns the result to your browser.

Successful web responses from /api/night and /api/pick carry cache-control: no-store. That statement covers those web responses, not the MCP endpoint.

If you use the MCP endpoint from Claude or another agent, that client sends the tool input and receives the result. The client's own privacy terms apply to its conversation, logs and retention.

Images loaded by your browser

A result can include an image URL supplied by Qloo. The page then loads that image directly from the URL's host. That host receives ordinary network metadata for the request, such as your IP address and user agent. It may also receive the referring page, depending on your browser's referrer policy. The app does not proxy those images.

Storage in the app

  • The app's own web code sets no cookies and uses no localStorage, sessionStorage, IndexedDB, analytics script or advertising script. Cloudflare and other network infrastructure can still process ordinary request metadata under their own policies.
  • The Worker configuration has no database, KV, R2, D1 or Durable Object binding. The app has no user accounts and does not write group profiles to a database.
  • The web night API at /api/night keeps a small cache in the memory of a Cloudflare Worker isolate. The key includes the city, member names, lowercased favourites and the optional date. The value includes the result. A matching request within 30 minutes can reuse the cached answer.
  • The cache holds at most 50 entries and removes the oldest entry when it is full. Expired entries are not removed by a timer. An entry can remain until eviction, until Cloudflare recycles the isolate, or until the isolate otherwise ends. The 30-minute period is a reuse window, not a deletion time.
  • The single-pick web API and both MCP tools have no such cache. The MCP plan_night_out tool calls the planning code directly.
  • The Worker code has no application logging statements. The Wrangler configuration in this source sets observability.enabled to false. That is a checked configuration, not a separate audit of the current deployment. It does not stop Cloudflare from processing ordinary network and request metadata as the hosting provider.

Provider policies and retention

Qloo's privacy policy, sections 5 to 7, says Qloo acts as a data processor for customer input, asks customers to pre-anonymize data sent through the API, and states that Qloo does not accept personally identifiable information through API calls. The same policy says Qloo may learn from associations between entities passed in an API request and use them to refine future output. These are Qloo's policies for its service. They do not make this app's input anonymous, and they do not establish what Qloo retains for a particular request.

This app does not automatically anonymize the text you type. Favourite text is sent to Qloo search unchanged. Do not enter personal or sensitive information as a name or a favourite.

Qloo's policy does not state a retention period for API requests. Actual Qloo-side retention for this app's requests is therefore not established by this notice.

Cloudflare's privacy policy says Cloudflare is a data processor for Customer Logs and for content that transits or is stored on its network, and that it processes network data including IP addresses and traffic routing information. Its retention section describes purposes and criteria rather than one fixed period for this app. Cloudflare's own policy governs that processing.

See the Qloo privacy policy and the Cloudflare privacy policy for their current terms.

What this app does not do

The repository contains no advertising, analytics or data-sale integration. The app does not book venues, take payments, create accounts or ask for private contact details.
